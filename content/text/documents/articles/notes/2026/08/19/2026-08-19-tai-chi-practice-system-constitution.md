# Tai Chi practice system constitution

## Admission

The `tai-chi-computer-system-services-section` is admitted as a child of the
personal health computer systems engineering services section. Its distinct
responsibility is to compose a personal computer system through which a
practitioner works with shared Tai Chi scientific resources,
movement-observation adapters, teachers, and portable practitioner-owned state.

No existing interface system owns this composition. Generic camera, schema,
filesystem, content-identity, HTTP, and state services remain generic
dependencies rather than being copied into this section.

## Generative parent

The personal health computer systems engineering services section is the
engineering parent because the system is scoped to one person's health
practice, devices, and state. Interface mediation remains a generic dependency;
Tai Chi science remains an upstream domain authority rather than a filesystem
parent.

## Cover

- `apps/tai-chi-practice-computer` — admitted now. A pure application
  computer over caller-supplied resources, records, observations, time, and
  ports. It has no ambient camera, filesystem, network, key, or clock authority.
- Browser face — declared, not yet admitted. It will render the computer and
  supply local browser ports.
- Local state adapter — declared, not yet admitted. It will use the existing
  dated-state and filepath-admission services.
- Teacher exchange — not admitted. It requires a later constitution covering
  identity, consent, encryption, retention, and revocation.

The current cover is therefore discrete and contains one admitted member.

## Inputs and outputs

Inputs are versioned Tai Chi science resources, portable practitioner state,
normalized skeletal observations, user actions, and explicitly supplied port
implementations.

Outputs are rendered application-state descriptions, new portable local
records, diagnostics, and explicit requests to ports. The pure computer does
not perform effects itself.

## Authority

The system may decide application workflow and presentation state. It may not:

- revise Tai Chi science or silently merge lineages;
- infer authority for medical, martial, spiritual, or teacher claims;
- retain raw camera media;
- write outside a practitioner-selected state root;
- upload records without a separately constituted exchange service and an
  explicit user act;
- make browser cache the sole copy of durable state.

## Non-ownership

The section does not own Tai Chi curricula or claims, generic pose-estimation
technology, generic JSON Schema semantics, generic filesystem custody, Emsenn's
records, teacher identities, or deployment infrastructure.

## Refusal conditions

The admitted computer must refuse malformed or version-unknown records,
unresolved curriculum references, contradictory coordinate metadata,
non-monotone frame sequences, unbounded paths, raw-media fields, and effects
for which the caller supplied no authorized port.

A pose trace is accepted as an observation, never as proof that a movement is
correct. This distinction is part of conformance, not user-interface wording.

## Authorization

The user authorized serious development of shared Tai Chi science and an
engineering-owned computer application on 2026-08-19, explicitly requiring the
personal section to contain only local data/state consumed by upstream
systems. That authorization admits this section and its pure first computer.
It does not authorize hosted accounts, network synchronization, teacher data
sharing, or raw-media retention.
